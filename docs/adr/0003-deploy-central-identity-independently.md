# Deploy Central Identity independently

Central Identity is an independently deployable OIDC identity provider for operator-owned Relying Parties, not the owner of their application deployments. On the shared production VM, Central Identity and Read in Peace each own a separate Compose project; a neutral, separately versioned infrastructure repository owns host Caddy, public TLS, and routing. Book Bidding remains independently deployed on Vercel. The optional shared local-development gateway does not set the production deployment boundary. A separate edge deployment costs more to operate than one shared stack, but a new Relying Party can join without becoming part of Central Identity's release or container network. The shared VM remains a common failure domain.

## Consequences

An operator-only CLI approves a distinct confidential OIDC Client for each Relying Party and environment, with its own backend-held secret and exactly one HTTPS sign-in callback; Reviewed Recovery may add one exact HTTPS callback. Callback paths are application-specific. There is no public client registration, self-service approval, or consent UI: only approved client records may authorize and exchange tokens, and only they skip consent. The persisted client record, not the provider library's immutable client cache or a process-environment allowlist, determines approval and disablement without a provider restart. Audit existing client records before enforcing this rule; preserve approved Bidding and Reading credentials. Disabling one client blocks new authorization and token exchange for that client, but neither ends existing Application Sessions nor revokes already-issued short-lived tokens; other Relying Parties continue.

Production cutover must back up and rehearse restoration of both databases, preserve the existing Reading database volume without starting two PostgreSQL containers on it, and move public ingress from the provider-owned Caddy to the neutral edge during a maintenance window. Existing local SSO pull requests remain scoped to local development; the current shared production stack stays in place until the separate production cutover is verified.
